# ADR 0055: Provider-owned runtime-rank fusion seam

## Status

Accepted

## Date

2026-09-02

## Board item

`HEPH-FUSION-SEAM-2026-09-02`

## Revision — 2026-09-02

Fusion cache entries now memoize `Result<ComputePipeline, Arc<str>>` inside
their per-key `OnceLock`. A first-use race waits for the canonical compilation
result, and validation failures replay as typed dispatch failures. This removes
duplicate WGPU compilation and avoids retrying a rejected generated source
without changing the public fusion seam.

## Cross-repository driver

Leto `LETO-DYNAMIC-LAYOUT-PROVIDER-SEAM-2026-09-02`; Coeus fused elementwise
and reduction evaluation.

## Context

Coeus currently authors dynamic fused WGSL in its consumer crate. That path
collects expression inputs, serializes layout metadata, creates bind groups,
compiles source, and submits a queue. Its elementwise and reduction paths
therefore duplicate Hephaestus's device ownership, layout validation, binding,
pipeline, and submission responsibilities. The provider already owns static
strided elementwise and axis-reduction families, but their const-rank operation
markers cannot represent a consumer expression DAG with a runtime input count.

## Decision

`hephaestus-core` adds three device-neutral pieces:

1. `DynamicStridedView<'a, B>` pairs a backend buffer with Leto's borrowed
   `LayoutDyn`. It is a copyable metadata view and never owns or copies data.
2. `FusedExpression<L>` is an open source-fragment contract. Its expression is
   generated by the consumer for dialect `L` and refers only to canonical
   `input_0`, `input_1`, … locals supplied by the provider. The source is a
   value, not a type-level operation marker, because expression DAG shape and
   input count are runtime data.
3. `FusedElementwiseOps` and `FusedReductionOps` are separate static-dispatch
   seams. The reduction seam uses a closed `FusedReduction` operation enum for
   sum, product, mean, minimum, and maximum. The trait methods remain generic
   over the provider and scalar and take borrowed view slices.

`hephaestus-wgpu` implements both seams through `WgpuFusionOps`. It owns the
WGSL wrapper, dynamic layout metadata buffer, binding-limit checks, buffer
provenance checks, broadcast validation, writable-output injectivity check,
axis/output-shape validation, error-scoped pipeline compilation, and the
per-device fusion pipeline cache. Cache keys compare the complete generated
source together with scalar, rank, input count, and kernel family, so a finite
digest collision cannot select the wrong pipeline.

The provider's shader ABI supports runtime ranks through the declared maximum
`MAX_FUSION_RANK`. This is a provider representation limit; Leto remains
arbitrary-rank. The expression is validated as a single WGSL expression
fragment before interpolation. All output addresses are derived from output
logical coordinates and the validated output layout, so non-contiguous views
remain zero-copy and overlapping writable views are rejected.

The first increment is one-shot dispatch because that is the current Coeus
call contract. Prepared fusion is a separate seam increment once a consumer
has a repeated-expression lifetime to bind; it must reuse the same provider
source and validation core rather than add another generator.

## Alternatives rejected

- **Leave fusion in Coeus and expose raw Hephaestus buffers.** Rejected:
  consumers would still duplicate shader ABI, validation, cache, and queue
  ownership; it is the storage-route gap this seam closes.
- **Represent every fused DAG as a new Hephaestus marker type.** Rejected:
  expression shape and input count are runtime variation and would require
  consumer-generated type families or cloned kernels.
- **Use `dyn FusedExpression` or a source hash alone.** Rejected: the hot
  dispatch remains generic, and a hash-only cache key is not collision-safe.
- **Put dynamic layout metadata in a uniform with a fixed bound.** Rejected:
  input count is runtime data and storage metadata has a clearer bounded
  resource contract; the provider checks the active device binding limit.

## Safety and failure model

The host validates every view against its device-owned buffer before metadata
upload. It rejects foreign-device buffers, incompatible broadcasts, address
width overflow, invalid output injectivity, unsupported rank, empty input
sets, invalid reduction axes or output shape, binding-limit exhaustion, and
unsafe expression fragments with typed errors. WGPU shader and bind-group
validation failures remain typed dispatch failures. No CPU fallback, retry, or
silent degradation is introduced.

## Consequences

Coeus can adapt its existing `ExprNode` source generation to one provider API,
then delete its consumer-owned fused WGSL, metadata pool, and raw submission
paths in a follow-on migration. Hephaestus gains a runtime-source seam without
coupling core to Coeus or to WGPU. Pipeline source strings are retained by the
per-device cache as part of the cache key; this is bounded by cache lifecycle,
not by input element count.

## Verification

Core tests compile a consumer-owned expression source against the generic
seams. Leto tests supply the layout laws. WGPU contracts differentially compare
fused elementwise and axis-reduction outputs with an independent host oracle,
and negative cases assert the typed validation failures before dispatch.
